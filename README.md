# MacTest Tools

Репозиторий посвящён **элементарным консольным утилитам для тестирования
PowerPC-компьютеров Apple (G3/G4/G5, Panther/Tiger/Leopard)** — мониторинга,
тестирования стабильности
и диагностики. Утилиты маленькие, автономные (чистый C, без внешних зависимостей),
пишутся под конкретную диагностику и хранятся здесь с историей.

## Целевые системы

- **ОС:** Mac OS X Leopard (10.5), Tiger (10.4) и **Panther (10.3.9)**;
  код собирается и корректно работает на всех трёх, артефакты собираются
  с переносимостью до 10.3 (слой `-mmacosx-version-min=10.3`; исключение —
  `smartinfo`, там `min=10.2`: SMART-API есть уже в Jaguar).
- **Процессоры:** PowerPC G3 (750), G4 (PMU-платформа: PowerBook, iBook,
  Power Mac «MDD», Mac mini G4) и **G5 (SMU-платформа: iMac G5,
  Power Mac G5)**; плюс Intel-стек (Leopard, MacBookPro3,1) —
  исследовательское направление (`fanmon/notes-intel.md`), PPC-артефакты
  кросс-собираются его тулчейном.
- **Канон сборки:** PPC-артефакты собираются кроссом на **intel-leopard**
  (решение 22.10.2026); PPC-машины — полигон прогонов бинарей из гита.
- **Машины, на которых ведётся тестирование:** iMac G5 (PowerMac8,1) с
  Tiger/Leopard; iBook G4 (PowerBook6,5) с Tiger; **PowerBook G4 15"
  (PowerBook5,6, 1.67 ГГц) с Leopard 10.5.8** (см. `fanmon/notes-pb15.md`);
  iBook G3 (PowerBook4,3 / PowerBook4,1) и PowerMac3,1 (Sawtooth G4-7400 @400,
  Tiger, см. `diskbench/readme.md`) — Panther 10.3.9-снимки в `fixtures/`;
  **PowerMac3,5 (Quicksilver G4-7450 @867, Tiger 10.4.11)** — первый RAID-0
  в парке (2×ST360021A на одном канале Ultra ATA/66, Apple software RAID:
  `diskbench/notes-quicksilver-raid0.md`), сенсоров в реестре нет
  (`fanmon/notes-quicksilver.md`); подробности создаются в `notes-<модель>.md`.
  При онбординге 26.10.2026 на ней стоял Leopard 10.5.8, на 27.10.2026 —
  Tiger 10.4.11 (`smartinfo/notes-quicksilver.md`).

## Принципы ведения репозитория

1. **Универсальная сборка.** Код компилируется так, чтобы работать на максимальном
   количестве машин Apple G3..G5: одна кодовая база, один Makefile,
   `gcc -std=gnu99 -Wall` без ворнингов как на Tiger/Leopard-тулчейнах
   (`powerpc-apple-darwin8`/`9`), так и на кросс-целях; обязательные слои
   сборки — три, см. §1 скилла `ppc-build` и Makefile'ы проектов.
2. **Только публичные API** (POSIX/IOKit public/CoreFoundation). Никаких приватных
   IOKit-интерфейсов, asm-вставок и заголовков не из релизных SDK. Утилита должна
   пережить смену версии ОС без правок.
3. **Честный отказ.** Если машина не подходит по архитектуре (нет узла реестра,
   нет PMU/SMU, не PowerPC) — утилита корректно завершается с понятным сообщением,
   а не падает.
4. **Записи экспериментов.** Каждый проект может сопровождаться `notes-*.md`
   с наблюдениями (например, `fanmon/notes-tiger.md`, `fanmon/notes-leopard.md`) —
   выводы фиксируются, гипотезы не теряются.
5. **Разделение стендов и канон сборки.** Репозиторий ведётся **на локальной
   машине** (macOS); на удалённые маки код выкладывается по SSH
   (`scp -O`, алиасы в `~/.ssh/config`). PPC-артефакты собираются **кроссом
   на intel-leopard** (канон, решение 22.10.2026); PPC-маки парка — полигон
   прогонов бинарей из гита, нативная там сборка — только при причине.
   Соглашение сессий: «на локальной машине» — репозиторий, «на удалённой
   машине» — тесты на маке парка.

## Бинарная совместимость (G4/G5, Tiger/Leopard)

Опытный факт: бинарник, собранный на старом тулчейне (Tiger, gcc 4.0.1
darwin8), корректно работает нативно-собранным и на Leopard, и на G5.
Почему и где ждём трудности:

- **Формат** — Mach-O 32-бит PPC одинаков у обеих ОС; ядро и dyld
  «версию Mac OS X» не различают.
- **Подтип CPU.** Тулчейн Tiger по умолчанию ставит подтип `ppc`
  (G3-совместимый): такие бинарники ядро загружает на любом 32-бит PPC.
  Leopard-тулчейн по умолчанию ставит `ppc7400` (выкинул бы бинарник на
  G3-only машине) — ещё одна причина собирать по-младшему.
- **Инструкции наших утилит** (`fmadd`, xor/shift, POSIX, древние
  IOKit-вызовы) есть от G3+; AltiVec-инструкции внутри fanmon/diskbench/
  pimem отсутствуют, поэтому они одинаково честны на 7447a и 970.
- **AltiVec — один ISA у G4 и G5** (128-бит vec_madd/ld/st), различаются
  только скорость/latency и число юнитов — «разным AltiVec» бинарник
  не пугается.
- **Направление сборки** — ключевое правило: *старая ОС → новая безопасно,
  новое → старое рискованно* (Leopard-бинарник может тянуть символы
  libSystem/IOKit, отсутствующие в Tiger). Собираем/раскатываем
  по-младшему тулчейну — а при кроссе с Leopard держим слой 3:
  `-mmacosx-version-min=10.3` (без него бинарь влечёт символы, которых нет
  даже в Tiger/Panther dyld: ловили на pimem — `___stderrp`).
- **Quirks уровня ОС** (не бинарные): `HW_CPU_FREQ` у Leopard отдаёт
  значение со сдвигом ×2³² (изловлен в pimem); P-state просыпания
  требует прогрева в бенчмарках.

## Протокол внедрения на новую машину

Порядок на каждую входящую в парк. SSH-часть — исполнительная версия
в скилле `park-onboarding`, сборочная — в скилле `ppc-build`.

1. **SSH-онбординг.** Старые sshd (Tiger/Leopard) договариваются со
   современным клиентом только ступенчато; чинить строго по лестнице,
   по ОДНОЙ шишке, фиксируя вывод:
   - host key: `-o HostKeyAlgorithms=+ssh-rsa`
     `-o StrictHostKeyChecking=accept-new`;
   - pubkey: `-o PubkeyAcceptedAlgorithms=+ssh-rsa` (ed25519 этим sshd
     не предлагать — отвергается молча);
   - ключа у машины нет (настоящая новенькая): парольный bootstrap через
     `expect` → сразу поставить наш ключ → вернуться на ключевой путь.
   Копирование всегда `scp -O` (sftp у старых sshd сломан — «realpath
   ... failed»), уступки те же. Итог: алиас в `~/.ssh/config` по итогам
   считанной идентичности (`hw.model`/`hw.cpusubtype`/частота — в
   комментарий); чек: `ssh -o BatchMode=yes <alias> 'echo OK'` работает
   без флагов.
2. **Тело бинарей — перед рассуждениями.** Слить ВЕСЬ репозиторий на
   машину:
   `scp -O -r ~/PowerTools <alias>:~/Projects/PowerTools`
   затем smoke всех консольных бинарей, каковы они в гите, короткими
   режимами:

   | утилита    | smoke            | ожидание |
   |------------|------------------|----------|
   | `fanmon`   | `./fanmon`       | таблица сенсоров; нет узлов — честный отказ |
   | `batinfo`  | `./batinfo`      | статус батареи; на десктопе отказ exit 1 |
   | `pimem`    | `./pimem -t 3`   | 4 ступени π + MEM-фаза, чексуммы |
   | `diskbench`| `./diskbench -s 8M -r 4M` | таблица read/write, чанки удалены |
   | `cpuburn`  | `./cpuburn -t 5` | busy ~100 %, печатает checksum |
   | `smartinfo`| `sudo ./smartinfo` | таблица дисков; `n/a` — честный отказ |

   **Слепой build на новой машине НЕ делается** — бинари из гита и есть
   проверка бинарной совместимости. Любая аномалия (не запустился,
   `Illegal instruction`, странный вывод) — записать в
   `notes-<модель>.md` того проекта немедленно, не откладывая в память.
3. **hwshot — выкачка реестра (ioreg).** На машину по `scp -O` идёт
   `fixtures/hwshot.sh`; снимок пишется рядом со скриптом под именем
   `hwshot-<модель>-<ОС>.txt.gz`; забираем обратно (`scp -O`), распаковываем
   локально (`gunzip`), кладём в `fixtures/`. Открытый вопрос: на
   ~10.3-машинах сообщалось о проблеме с архиватором (root cause не
   установлен; скрипт сейчас молча глушит ошибки gzip и молча даёт
   fallback на `.txt`) — при первом живом визите на Panther-машину
   прогнать и зафиксировать, что происходит.
4. **Пересборка — только при причине; канон = intel-leopard.** Причины:
   бинарь не запустился/упал (инцидент из п.2), нужна правка кода, новая
   система требует иной точки сборки. Канон (решение 22.10.2026): кросс на
   **intel-leopard** (10.5 + Xcode, `gcc 4.0.1 build 5493`) — Makefile'ы
   парка несут одинаковые флаги для обоих хостов, ТРИ слоя G3-safe:
   `-arch ppc` (кросс-цель) + `-mcpu=G3` (инструкции/шедулер 750) +
   `-Wl,-force_cpusubtype_ALL` (подтип ppc/ALL) +
   `-mmacosx-version-min=10.3` (dyld Panther). Верификация (§3
   скилла `ppc-build`): otool `PPC ALL`, VA-мнемоник 0, дымовой прогон
   на PPC-машине, md5 — артефакт в гит.
5. **Итог посещения машины** — в notes (`notes-<модель>.md`) + обновление
   `pimem_baseline.md` (если мерили π/MEM) или записок diskbench;
   binary результаты и новые hwshot-снимки — в git.

G3-машина подтверждает правило: Tiger-бинарь из git завёлся/посчитал
без пересборки.

### Заготовка под G3 — снята, реальность

G3-машина в арсенале есть (iBook G3 Dual USB, PowerBook4,3, 750-family
800 МГц), но пришла **с уже поставленным Tiger 10.4.11** — новинкой той
эпохи. Итоги: тот же тулчейн gcc 4.0.1, наш Tiger-бинарник `ppc` грузится
и работает без препятствий (batinfo — подтверждено; платформенные
особи линия сенсоров ниже). Таблица замеров парка — `pimem_baseline.md`. Сенсоров для fanmon на этой платформе
**в реестре нет** — не из-за «слякоти ОС», а конструктивно
(device-tree не объявляет `*-sensor` узлов; мониторинг фан/темп держит
на себе автономный чип ADM1030 — пользователям Apple этих цифр не
выкладывал никакой драйвер). Детали и обоснование: `fanmon/notes-g3.md`.

G3/машина старее Tiger — уже реальность (10.3.9-машины, см. ниже):
правило младшего тулчейна разомкнуто кроссом — артефакты собираются на
intel-leopard с третьим слоем `-mmacosx-version-min=10.3` и потому не
требуют 10.3-тулчейна. Если машина принесёт ОС **старее 10.3** (10.2 и
ниже) — снова актуальны проверки бывшей заготовки: `gnu99` старым
тулчейном, `cpuburn` без AltiVec, sysctl-нюансы; точка кросс-сборки в
этом случае пересматривается (скилл `ppc-build`).

### Panther уже в парке — не гипотеза

Снимки 10.3.9 сняты с PowerBook4,1, PowerBook4,3 и PowerMac3,1
(`fixtures/`, 21–24.10.2026) — 10.3.9-машины работают и являются младшей
границей парка. Следствия, уже учтённые: третий слой
`-mmacosx-version-min=10.3` во всех Makefile'ах (иначе кросс с Leopard
на 10.3 не грузится), запуск бинарей из гита на 10.3.9 — часть smoke на
внедрении (шаг 2 протокола). Живые итоги прогонов на Panther — по мере
визитов в notes.

## Проекты

| проект        | назначение |
|---------------|-----------|
| **cpuburn**   | Генератор нагрузки CPU для 970/G4: держит все скалярные конвейеры (2 FPU FMADD, ALU, LSU) одновременно; потоки, duty cycle, режимы `fp/int/mem/mixed`; печатает checksum как доказательство реальной работы. **AltiVec удалён** (решение 22.10.2026) — умолчательное состояние сборки БЕЗ VA. Автономен, ничего не мониторит — только греет и грузит. |
| **diskbench** | Бенчмарк диска: линейные и случайные чтение/запись (`pread/pwrite`, `F_NOCACHE/F_FULLFSYNC` с фолбэками). По умолчанию честные цифры без кэша ОС; параметризуется размерами и местом чанка. |
| **fanmon**    | Консольный монитор вентиляторов/температур/электрики через IORegistry, публичный IOKit API. **Два пути данных, auto-detect: SMU (G5)** — словари `IOHWSensors`/`IOHWControls` платформенного плагина; **PMU (G4)** — фолбэк на сервисные узлы `IOHWSensor` (AppleHWSensor). Режим снимка и `-w N`. Работает на iMac G5 (Tiger/Leopard) и iBook G4; на iBook G3 честный отказ — сенсорных узлов в DT не объявлено (см. `fanmon/notes-g3.md`); особенности «замороженных» actual на SMU и валидного 0 rpm на PMU — в `fanmon/notes-*.md`. |
| **pimem**    | Бенчмарк-дуэт: π-ступени Ooura AGM/FFT (SuperPI-класс, 128k–4M знаков, `-O1`) + MEM-фаза (copy MB/s + walk ns/hop). Один исходник `pimem.c` на все арки, артефакты `pimem-ppc`/`pimem-intel` в гите (`ppc/ALL`, Panther+), кросс-сборка на intel-leopard — таблица `pimem_baseline.md`. |
| **batinfo**   | Статус батареи (PowerPC ноутбуки): PMU-путь (`IOBatteryInfo` — напряжение упаковки, остаток, полная/проектная ёмкость, health %, циклы, флаги) + smart-battery путь под будущие машины + сенсоры location~BATTERY (температура). Серийник/ячеечные напряжения в 10.4 PMU-стеке недоступны — см. readme. |
| **smartinfo** | Read-only SMART по всем ATA-дискам: общий статус + таблица атрибутов с порогами (три команды: `ReturnStatus`, `ReadData`, `ReadDataThresholds`). Никаких self-test'ов и enable/disable — в коде их нет. Детект тремя путями (`SMART Capable`, `ATASMARTUserClient`, `ATA Features & 0x20`) — работает от Jaguar 10.2 (IDENTIFY вызывается только с 10.3, чтобы не читать за vtable) до Leopard, включая G5 K2 SATA и Intel AHCI. Сводка по `5/197/198/199/9/194`, вердикт OK/WARN/FAIL, `-a` — все 30 атрибутов. |
