# traycpu

Трей-гейдж загрузки CPU: пункт в меню-баре ` CPU: NN% ` (среднее за последнюю
секунду, обновление 1 Гц), клик открывает меню с единственным пунктом
**«Выход»**. Без главного окна, без док-иконки. Собран крестом
(intel-leopard 10.5 → PPC Panther 10.3.9), запущен и отгружен на живой
PowerMac3,1 Panther 10.3.9 (24.10.2026).

## Как считает

Нагрузку НЕ опрашиваем. Раз в секунду читаем накопительные тики ядра через
`host_statistics(HOST_CPU_LOAD_INFO)` (API живёт с 10.0):

```
pct = 100 × (1 − idle_Δ / (user+sys+nice+idle)_Δ)
```

Дельта двух снапшотов через 1 с и ЕСТЬ среднее за эту секунду — ядро
интегрировало нагрузку машинно-точно между визитами. Отношение дельт —
единицы тиков не важны; `unsigned` delta переживает uint32 wrap; квант
тикера ~10 мс ⇒ разрешение ~1%. При `total_Δ == 0` (спячка/тишина)
держим прошлое значение.

## Рендер в трее (выстраданная калибровка)

Panther-статус-пункт не авторесайзится под `setTitle:` — клиппит справа.

Строка рендерится с паддингом ` CPU: NN% ` (лид+трейл пробелы гасят
дрожание ширины пропорционального шрифта). Длина пункта фикс:

| длина  | что увидели на живой машине                       |
|--------|---------------------------------------------------|
| 40 pt  | клип до `1` (`NN%` съеден)                        |
| 60 pt  | клип до ` CPU: 1 `                                |
| 76 pt  | на 90–100% съедается правая часть `%`             |
| 86 pt  | на 100% `%` ещё чуть подрезается                  |
| **96 pt** | **чисто, включая ` CPU: 100% ` — принято (10/10)** |

Если дрожание ширины всё же заболит — след. итерация: кастомный NSView
внутри пункта с моноширинным Monaco (есть в Пантере).

## Дока

`LSUIElement=1` в Info.plist (ключ с 10.0): приложение-агент — НЕ появляется
ни в доке, ни в cmd-Tab. Иконка приложения при работе — только в трее.
Проверено на живой машине: «в доке нет лишних иконок».

## Меню

Пункт статуса с прикреплённым `NSMenu` (один пункт «Выход», `-terminate:`
через target). Меню раскрылось «широко, охватывая всю надпись» — ширина
96 pt честно отдаётся popup'у. Нюанс: NSTimer в NSDefaultRunLoopMode —
пока меню открыто, счётчик стоит (косметика).

## Рецепт

Кросс-сборка на intel-leopard (хост 10.5 intel → цель 10.3 ppc), канон
парка + легаси objc:

```sh
gcc -arch ppc -mcpu=G3 -Wl,-force_cpusubtype_ALL \
    -mmacosx-version-min=10.3 -std=gnu99 -O1 -Wall \
    -fobjc-abi-version=1 \
    -x objective-c traycpu.m -o traycpu \
    -framework Foundation -framework AppKit
```

- `-fobjc-abi-version=1` — только objc1-раскладка классов (Panther-runtime;
  проверка `otool -ov`: класс декодируется в легаси-форме, `ProbeTarget`,
  методы `quit:`/`tick:`).
- ObjC — одни objc1-конструкции: подкласс NSObject, простые методы, никаких
  properties/blocks.
- Кириллица «Выход» — UTF-8 строка сорса через `stringWithUTF8String`.
- Аудит артефакта: **PPC ALL**, VA=0,
  md5 `9f616fbc016927a88e0d47878887da9f` (финальная сборка, 96 pt).

`make` собирает `traycpu` + бандл `TrayCPU.app` (plist + MacOS/traycpu).

## Запуск по ssh — тот же протокол, что у tray-probe

Несжатый `tar` (на чистой Пантере нет gzip) → `scp -O` →
`open ~/TrayCPU.app` — единственный путь запуска: LaunchServices поднимает
процесс в консольной сессии (`-psn_…` в `ps`).

## Верификация на живой машине (PowerMac3,1 Panther 10.3.9, 24.10)

Градуировка гейджа циклами cpuburn (уже деплоен на машине):

| цикл  | cpuburn                      | трей                     |
|-------|------------------------------|--------------------------|
| 1     | -t 20, busy 100.0%, rc=0     | взлёт/откат — ок        |
| 2     | -t 20, busy 100.0%, rc=0     | ок                       |
| 3     | -t 20, busy 100.0%, rc=0     | ок; но клип 76 pt пойман |
| 4     | -t 15, busy 100.0%, rc=0     | ок; 86 pt впритык        |
| 5     | -t 12, rc=0                  | 96 pt — чисто, принято   |

Финальный аккорд юзера: «10 из 10»; выход через меню погасил процесс.
Гейдж сам живёт в ~0.1–1% CPU.

## Ограничения

- Первая секунда после запуска показывает `--%` (нужна первая дельта).
- Пока открыто меню — счёт стоит (таймер в default-mode).
- Разрешение ~1% (квант тикера), системно-широкая метрика (все процессы,
  включая сам traycpu — тень в сотые процента).
