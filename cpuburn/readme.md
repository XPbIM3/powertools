# cpuburn / burn

Автономная утилита-нагрузчик процессора для PowerPC Mac (Mac OS X 10.4/10.5).
Никак не связана с мониторингом — только генерирует нагрузку.

## Идея нагрузки (под архитектуру G5)

Процессор 970 суперскалярный (2 FPU + 2 ALU + LSU), поэтому
загрузчик старается держать **все скалярные конвейеры занятыми одновременно**:

- 16 независимых `fmadd`-цепочек: a[i] = a[i]*x + 0.5 (latency FP ~6 циклов -
  длина 16 гарантированно перекрывает задержку, оба FPU не простаивают)
- integer: 4 независимых xorshift32-цепочкиRolAt (xor/shift, latency 1 такт)
- вращающийся буфер 8 МБ на поток (контроллер памяти)

Каждое ядро собирает чексумму и печатает её в конце:
доказательство, что работа реально выполнялась (и не была выкинута
оптимизатором). Аккумуляторы рециклируются при переполнении, чтобы
плавающая точка не уводила в inf/NaN.

## Флаги

```
cpuburn [-n THREADS] [-t SECONDS] [-m MODE] [-h]
  -n N   число потоков (default 1; >1 = oversubscription одноядерных)
  -t S   длительность, секунд (default 600 = 10 мин)
  -m M   режим fp | int | mem | mixed (default mixed)
  -h     справка
```

Политика работы: **нормальный приоритет** (никакого `nice` — утилита и так
не блокирует системные процессы) и **полная нагрузка всегда** — duty cycle
(`-d`) и игры с приоритетами убраны как лишние; «жжём» на 100 %
с рождения. Реальная занятость видна в итогах: busy ms и %.

## Сборка

- **Канон пересборки** (решение 22.10.2026, как у pimem/diskbench): кросс-сборка
  на **intel-leopard** (`i686-apple-darwin9-gcc-4.0.1`, build 5493, Leopard 10.5
  + Xcode) — кроссит PPC-цель штатно. Нативная сборка на PPC-машине парка
  остаётся валидной (те же флаги из Makefile).
- Три слоя G3-safe в Makefile (флаги одинаковы на обоих хостах):
  `-arch ppc -mcpu=G3 -Wl,-force_cpusubtype_ALL -mmacosx-version-min=10.3`.
  Без minos 10.3 кросс с Leopard влечёт за собой символы libSystem,
  отсутствующие на Panther (`___stderrp`). Аудит после сборки:
  `otool -hv` → **PPC ALL**; `otool -tv | grep -icE 'v(a|m)[a-z]+'` → **0**
  (отсутствие VA — решение 22.10.2026, ниже).
- **AltiVec удалён (решение 22.10.2026):** умолчательное состояние
  сборки — БЕЗ AltiVec. Код-пути `vec`/`mixed`-VA, runtime-guard
  `has_altivec()` и флаг `-faltivec` вырезаны; в бинаре VA-инструкций
  НЕ ДОЛЖНО БЫТЬ (otool -tv = 0). Режимы: `fp` | `int` | `mem` |
  `mixed` (mixed = fp + int + mem).
- Смок расширенного бинарника (23.10.2026, PowerMac G4 7400@400
  Sawtooth, Tiger 10.4.11, md5 `7d9f570e…` байт-в-байт): mixed 3 с —
  busy 100.0 %, чексумма выдана; `-m vec` = "unknown mode" отказ.

```sh
# канон: кросс на intel-leopard (флаги уже в Makefile)
ssh intel-leopard
cd ~/Projects/burn
make clean && make        # затем аудит otool и слияние артефакта в гит (§3 скилла ppc-build)
# нативно (валидно): ssh <ppc-машина> — те же флаги из Makefile
```

## Запуск

```sh
./cpuburn -t 5              # 5 с полной нагрузкой
./cpuburn                   # 10 минут полной нагрузки (default)
./cpuburn -t 5 -n 2         # 2 потока на одноядерном G5
./cpuburn -m fp -t 5        # нагрузка только FP
```
