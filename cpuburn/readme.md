# cpuburn / burn

Автономная утилита-нагрузчик процессора для PowerPC Mac (Mac OS X 10.4/10.5).
Никак не связана с мониторингом — только генерирует нагрузку.

## Идея нагрузки (под архитектуру G5)

Процессор 970 суперскалярный (2 FPU + 2 ALU + LSU + AltiVec), поэтому
загрузчик старается держать **все конвейеры занятыми одновременно**:

- 16 независимых `fmadd`-цепочек: a[i] = a[i]*x + 0.5 (latency FP ~6 циклов -
  длина 16 гарантированно перекрывает задержку, оба FPU не простаивают)
- integer: 4 независимых xorshift32-цепочкиRolAt (xor/shift, latency 1 такт)
- AltiVec: vfmadd-цепочки + vec_ld (LSU)
- вращающийся буфер 8 МБ на поток (контроллер памяти)

Каждое ядро собирает чексумму и печатает её в конце:
доказательство, что работа реально выполнялась (и не была выкинута
оптимизатором). Аккумуляторы рециклируются при переполнении, чтобы
плавающая точка не уводила в inf/NaN.

## Флаги

```
cpuburn [-n THREADS] [-t SECONDS] [-d FRACTION] [-m MODE] [-P] [-h]
  -n N   число потоков (default 1; >1 = oversubscription одноядерных)
  -t S   длительность, секунд (default 10)
  -d F   duty cycle 0.01..1.00 (default 1.0 = непрерывная работа)
  -m M   режим fp | int | vec | mem | mixed (default mixed)
  -P     не снижать приоритет (default: процесс запускается с nice +10,
         чтобы SSH-сессия оставалась отзывчивой)
  -h     справка
```

Квант планирования: 10 мс (работа + сон в зависимости от `-d`).
При реальном вкладеprocess занятости видно в завершении: busy ms и %.

## Сборка

- **ОС:** Mac OS X 10.4.11 (Tiger), iMac G5 PowerPC
- **Тулчейн:** Xcode 2.5 11 GCC 4.0.1
- Флаги: `-std=gnu99 -O2 -Wall -faltivec` (AltiVec builtins включены)
- Сборка: 0 warnings

```sh
ssh tiger
cd ~/Projects/burn
make clean && make
```

## Запуск

```sh
./cpuburn -t 5              # 5 с полной нагрузкой, все ядра
./cpuburn -t 10 -d 0.5      # 50 % нагрузки
./cpuburn -t 5 -n 2         # 2 потока на одноядерном G5
./cpuburn -m fp -t 5        # нагрузка только FP
```
