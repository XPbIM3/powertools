# tempgauge

**Справочная информация: как собирать тулзы для тре.** Четвёртый член
парк-каркаса (`carbon-probe` → `traycpu` → `diskgauge` → здесь) — и
первый, собранный **нативно на собственной машине** (Leopard ↔ Leopard),
без кросса. Смысл — рецепт, а не утилита: гейдж показывает температуру
CPU и попутно записывает всю кухню её получения.

```
 CPU: D078 P065 C
```

D = диод ядра, P = proximity пакета. Оба поля фиксированные 3-знаковые
с ведущими нулями, кап 199, целые градусы.

## Как собиралось

Натив-хост `intel-leopard` (MacBookPro3,1, Mac OS X 10.5, gcc
i686-apple-darwin9-gcc-4.0.1 b5493) — сборка **для самого себя**:
канон-флаги парка с вычеркнутой кросс-частью (никаких `-arch ppc`,
`-force_cpusubtype_ALL`, `-mmacosx-version-min=10.3` — Leopard-runtime
переваривает дефолтный objc-ABI сам):

```sh
gcc -std=gnu99 -O1 -Wall tempgauge.m -o tempgauge \
    -framework Foundation -framework AppKit -framework IOKit
```

Аудит: `file tempgauge` = Mach-O i386. Бандл `TempGauge.app`
(Info.plist + MacOS/бинарь), `open ~/TempGauge.app` через ssh — тот же
LaunchServices-путь, `-psn_…` в `ps` подтверждает консольную сессию.

| артефакт | md5 |
|---|---|
| бинарь гейджа | `fac9302f27372bf32417b9d8b9d99c09` |
| пробник | `21daa57691891d91a7ae73af514bac49` |

## Счётчик: AppleSMC юзер-клиент (рецепт)

ioreg **не светит** значения SMC-ключей (проверено на этой машине —
в реестре только косвенные следы). Значения читаются приватным
юзер-клиентом — де-факто канон от devnull (2006) / smcFanControl,
одинаковый у всех эпохальных температурных тулз:

1. `IOServiceMatching("AppleSMC")` → `IOServiceGetMatchingServices` →
   `IOServiceOpen(dev, task, 0, &conn)`
2. `IOConnectCallStructMethod(conn, 2, &in, sizeof, &out, &sz)` —
   селектор **2**, внутри `data8 = команда`:
   `5 = READ_BYTES`, `8 = READ_INDEX` (перечисление ключей по порядку),
   `9 = READ_KEYINFO` (тип/размер ключа)
3. Ключи — 4-байтные коды (`TC0D` и т.п.); рабочая лошадка — структура
   `SMCKeyData_t` (полный layout в коде: key, vers[6], pLimitData,
   keyInfo, result, status, data8, data32, bytes[32])
4. Декод `sp78` (big-endian, 2 байта): `(b0*256 + b1) >> 2 / 64.0` —
   эквивалентно `/ 256`, градусы с точностью ~0.004

Разведка ключей — `tmpprobe` (`./tmpprobe N`: ходит по индексам 0..N,
печатает ключ/тип/значение/hex — на ней машина проявилась вся).
На MBP3,1 из 245 ключей CPU-температуры: **TC0D** (диод) и **TC0P**
(proximity) — и всё.

## Урок «обоих ядер»

Запрос юзера «индикация обоих ядер» упёрся в железо: у MacBookPro3,1
**ровно один CPU-диод** — `TC1D`/`TC2D`/`TCx`-пар в ключевом
пространстве нет, чипсет не разводит по ядрам (ср. MacPro, где живут
`TCAH`/`TCBH`). Честный второй показатель — proximity пакета (`TC0P`).
Гейдж рендерит MAX по кандидатам:

- `D`: `TC0D`, `TC1D`, `TC2D`, `TC3D`, `TCAH`, `TCBH` (макс по диодам)
- `P`: `TC0P`, `TC1P`, `TCAH`, `TCBH` (макс по proximities)

на однодиодных машинах — ровно как здесь; на многодиодных — тоже
работает. Максимум — консервативная семантика: греется самое горячее.

## Урок отступов (закрывает спор ширин)

На Пантере +50 pt к мелкошрифтовой мере ещё съедал пиксели. Leopard —
точно те же грабли. Вывод рецепта:

> мелкая гарнитура (`smallSystemFontSize`) систематически недомеряет
> против барного рендера на всех проверенных OS X.

Фикс, переставший быть подбором: мерить `systemFontOfSize:0` (13-пт
лицо, заведомо шире любого барного рендера). Длина строки от формата
(%03d) — константа, так что одного пересечения мерной гарнитуры с
барным хватает навсегда — ни мигания, ни клипа.

## Верификация на живой машине (MBP3,1 Leopard 10.5)

Гейдж и пробник читаются параллельно; профиль ожиданий:

```
покой:              D 49.9 / P 47.9   ->  CPU: D050 P048 C
2 ядра горят 30 с:  D 64.6→78.0, P 47.8→58.1  (D ведёт, P подтягивается)
12 с после стопа:   D 62.5 / P 59.9   (диод остывает быстрее пакета)
```

- выход через меню → процесс чисто гаснет (`ps` пуст)
- гейдж сам — 0.0–0.4% CPU
- нагрев для тестов: `dd` на Leopard не годится (упёрся в память,
  5 GB/s, 0.05 с) — ядра грели двухядерным `while`-спином из ssh

## Границы

- `D--- P---` первые секунды после старта и при нечитаемом ключе
- значения ≤0 или ≥200 C (читаемые, но бредовые) удерживают прошлый
  показ
- Пантора-вариант (если понадобится живая трей-тулза на PPC): собирается
  кроссом по рецепту diskgauge, каркас тот же
