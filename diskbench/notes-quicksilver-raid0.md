# diskbench: PowerMac3,5 Quicksilver — RAID-0 из двух IDE на одном канале ATA/66

Дата: 26.10.2026 · Машина: `quicksilver-g4-867` (10.0.1.33, PowerMac3,5,
G4-7450 @867 МГц, 1 ГБ, Leopard 10.5.8) · Полный снимок реестра:
`fixtures/hwshot-PowerMac3,5-10.5.8.txt.gz`.

## Конфигурация массива (важно для трактовки цифр)

- **Apple software RAID v2, Stripe** (не железная карта), имя тома `rd`,
  статус **Online**, оба члена Online, «Apple RAID Version: 2».
- Члены: **2× ST360021A** (Seagate Barracuda ATA IV, 60 ГБ, 7200 об/мин),
  по 55.9 GiB, у обоих `SMART Status: Verified`.
- Схема каждого члена: `Apple_partition_map` + `Boot OSX` 128 МБ + `Apple_RAID`.
- Том: `/dev/disk2`, 111.5 GiB, HFS+ **journaled**, это **корневой** `/`,
  свободно 104 GiB.
- **Оба диска на одном канале**: `ata-4@1f000`, clock-id **`uataat66`**
  (Ultra ATA/66), master+slave (`hd`/`ultra0` = disk@0, `ultra1` = disk@1).
  Второй канал `ata-3@20000` (`ataaaa66`) занят оптикой.
  Следствие: **общий потолок шины ~66 МБ/с**, страйп не получает параллелизма
  двух независимых шин — только перекрытие seek'ов двух голов.
- **Stripe size не публикуется**: `diskutil listRAID` и ioreg его не отдают,
  а `diskutil createRAID` в 10.5 опции размера не имеет (Apple default).
  Значение честно помечено как **unknown** — не выдумываем.
- `ioreg`: `AppleRAIDStripeSet` / `AppleRAIDMember`, `AppleRAID-LevelName=Stripe`,
  `AppleRAID-SetStatus=Online`, `AppleRAID-CanAddSpares=No`.

## Прогоны: nocache, дефолт 512M/16M (блоки 4M/4K), один и тот же `-p`

```
pass 1
linear write       20.816 s      24.6 MB/s
linear read        35.235 s      14.5 MB/s
random write       10.100 s       1.6 MB/s         406 ops/s  avg  2465.9 us/op
random read        21.821 s       0.7 MB/s         188 ops/s  avg  5327.5 us/op

pass 2
linear write       20.657 s      24.8 MB/s
linear read        34.873 s      14.7 MB/s
random write       10.213 s       1.6 MB/s         401 ops/s  avg  2493.5 us/op
random read        22.104 s       0.7 MB/s         185 ops/s  avg  5396.4 us/op
```

Пассы совпали в пределах **<2 %** — кеш-утечки нет (методика E1 из
`notes-nocache.md`: pass2 не быстрее pass1).

## Контроль кеша: тот же чанк с `-c`

```
linear write       19.488 s      26.3 MB/s
linear read         8.558 s      59.8 MB/s
random write        3.159 s       5.1 MB/s        1297 ops/s  avg   771.2 us/op
random read         5.459 s       2.9 MB/s         750 ops/s  avg  1332.7 us/op
```

Чтение выросло **14.6 → 59.8 МБ/с (4×)** — это UBC, и это же доказывает, что
nocache-цифры честные. Кешированное чтение упирается в **потолок ATA/66**
(~60 МБ/с), что подтверждает топологию «два диска на одном канале».

## Выводы

1. **Страйп не дал удвоения**: 24.7 МБ/с запись, 14.6 МБ/с чтение — уровень
   одиночного IDE-диска (Sawtooth: 30/20 в Tiger). Причина видна в дереве
   устройств: оба члена сидят на одном канале Ultra ATA/66 master+slave,
   суммарная шина и есть потолок.
2. **Random 4K страйп не помогает** — 185–406 IOPS, ровно уровень одной
   головы: 4K-блок всегда попадает в один член, а вторая голова добавляет
   конкуренцию за seek. Это подтверждает вывод из `notes-nocache.md` (RAID 0
   на G5: random не масштабируется).
3. **write > read в nocache** — та же асимметрия, что на G5 (99/120–139) и
   Sawtooth (30/20): это свойство честного nocache-режима (запись уходит в
   кеш привода/журнал, чтение ждёт пластинки), а не артефакт RAID.
4. Проверено **без записи в члены массива**: бенчился только том `disk2`
   целиком; индивидуальные члены не трогались (запись в member = разрушение
   страйпа).
5. Free space на томе 104 GiB — дефолтный чанк 512M/16M проходит с запасом;
   `diskbench` сам печатает `need ~528 MB`.

## Открытые вопросы

- Stripe size остался неизвестным; если понадобится, можно попробовать
  прочитать заголовок RAID v2 с членов (read-only) и разобрать поле.
- Разброс по зонам пластин на страйпе не мерили (один `-p`); для паспорта
  можно повторить на другом смещении/другом томе.
- Сравнить с одиночным членом нельзя без разрушения массива — сравниваем
  только с другими машинами парка.
