# Заметки: iBook G3 (ibook-g3, 10.0.1.96)

Машина: `PowerBook4,3` «Dual USB», 750-family G3 800 МГц (1 core,
384 МБ), ОС — **Tiger 10.4.11 (Build 8S165), Darwin 8.11.0** — система
новее ноутбука (2001 год против 2005). Тулчейн тот же, что на
iBook G4: gcc 4.0.1 (build 5370), плюс есть gcc-3.3.

## Вывод: fanmon на G3 выпадает честно — сенсоров в реестре нет

Проверено дампом `ioreg -l -w 0` (3247 строк):

1. **Класса `IOHWSensor` / `IOHWControl` в системе нет вообще** — ни
   одного узла. `AppleHWSensor.kext` v1.4.5 присутствует на диске, но
   **не загружен** (`kextstat`: из термически-ориентированных только
   AppleI2C 3.5.0d2 и ApplePMU 2.3.4d1).
2. Почему не загрузился: его personalities матчатся с device-tree
   по `device_type` = `temp-sensor` / `fanspeed-sensor` / `voltage-sensor`
   / `current-sensor` / `power-sensor` / `adc-sensor` / ...-control.
   В DT этой машины **ни одного такого узла не объявлено** — нечего
   матчать, драйверу честно нечего делать.
   (Не «Тигр не может выудить»: данные для выуживания не публикуются.)
3. `ApplePMU` под `via-pmu` (AppleVIADevice) публикует только батарею
   (`IOBatteryInfo` — то же, что на G4; читает batinfo) и энергоменеджер.
   PMU-путь fanmon ищет AppleHWSensor-узлы с `current-value` — на G3
   их никто не создаёт.
4. Не-живые данные: DT-узел `power-mgt` содержит `thermal-info =
   <030102>` (3 байта статической конфигурации прошивки PMU, не
   сенсорный поток) и `prim-info` (статика батарейной прошивки).
   `PMUReleaseInfo` узла ApplePMU: release 0xd0, version 0x80,
   family 0x0c — версия PMU-прошивки.

## Кто на самом деле держит температуру/вентилятор: чип ADM1030

В DT на KeyLargo-I2C-шине (узел `i2c` → `PPCI2CInterface`) есть **`fan@158`**:
- `device_type` = `adm1030`, `device-id` = <0x30>, `company-id` = <0x41>,
  reg = 0x158;
- ADM1030 (Analog Devices) = датчик удалённой температуры (CPU-диод) +
  PWM-контроллер вентилятора с **аппаратными порогами**: обороты он
  держит сам, автономно, без участия ОС;
- **у `fan@158` нет ни одного IOService-ребёнка** — ни один драйвер не
  приписался, значения в реестр не попадают.

Второй узел шины (cereal@1c0) — не сенсор.

## Что это значит для наших утилит

- `fanmon` на G3: вывод «no IOHWSensors/IOHWControls owner found...» —
  **корректный, честный отказ**, код менять не надо.
- `batinfo` на G3: работает полноценно (PMU-путь универсален G3/G4) —
  проверено на этой машине.
- `cpubench`: работает (см. `cpu_bench_baseline.md`, паспорт G3).
- Лезть дальше (чтение регистров ADM1030 через полуприватный
  `I2CUserClient`: удалённая температура = reg 0x0D, TACH = рег 0x24/0x25,
  PWM duty = reg 0x07) — имеет смысл ТОЛЬКО при практической
  необходимости порогового теста G3. Решение: **не тратимся**:

  > Если даже Apple собственным стеком не отдаёт данные с этой машины —
  > незачем добывать их вне публичного интерфейса.

## Осторожность на будущее (для следующих сессий)

- ssh-алиас `ibook-g3`, вход по ключу установлен (expect с паролем).
- Ожидания по скорости: G3 **медленный**, и на одном ядре любой фон
  (Spotlight-индексация, установщики) даёт load > 1 и портит цифры
  cpubench — один полный перегон у нас уже съело это. Перед замерами
  проверять `uptime/load` и top (`mds`/`mdimport`).

  batinfo-паспорт совпадает с той машиной до mAh.
