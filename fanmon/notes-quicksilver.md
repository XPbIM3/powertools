# fanmon: PowerMac3,5 Quicksilver — сенсоров в реестре нет (честный отказ)

Дата: 26.10.2026 · Машина: `quicksilver-g4-867` (10.0.1.33, PowerMac3,5,
G4-7450 @867 МГц, Leopard 10.5.8) · Снимок: `fixtures/hwshot-PowerMac3,5-10.5.8.txt.gz`.

## Наблюдение

```
$ ./fanmon
fanmon: no IOHWSensors/IOHWControls owner found and no IOHWSensor nodes (unsupported machine?)
exit=1
```

Утилита отработала по принципу «честный отказ» (принцип 3 README): не упала,
не напечатала пустую таблицу, вернула exit 1 с понятным сообщением.

## Что говорит реестр (полный hwshot, 7 плоскостей)

| искомая строка | вхождений в дампе |
|---|---|
| `IOHWSensor` | 0 |
| `IOHWControls` | 0 |
| `IOHWMonitor` | 0 |
| `fanspeed` | 0 |
| `AppleHWSensor` | 0 |
| `sensor` (в любом регистре) | 0 |
| `fan` (в любом регистре) | 0 |

Слова `sensor`/`fan` не встречаются в снимке **вообще** — не только сервисов
нет, но и узлы device-tree их не объявляют. I2C-контроллеры при этом живы и
видны (`i2c@18000` — `AppleMacIODevice`, `i2c@f8001000` — `IOPlatformDevice`,
`PPCI2CInterface`), но ни одного клиента-сенсора на них не посажено.

## Трактовка

- Это **не** «слякоть ОС» и не регресс fanmon: на Quicksilver (2001) Apple не
  описывает сенсоры в device-tree, а обдув, как и на Sawtooth, рулит
  PMU-прошивка. Пользовательских цифр температур/оборотов в IORegistry нет.
- Класс машины для fanmon = **десктопный G4 без телеметрии** (тот же вывод,
  что `notes-g3.md` для iBook G3, но по другой причине: там нет узлов
  `*-sensor`, здесь — нет вообще ничего сенсорного).
- Поэтому `cpuburn` на этой машине идёт «слепым» (см.
  `cpuburn/notes-g4-quicksilver.md`): температуру/обороты monitor-слоем
  не проверить, только косвенно — по отсутствию троттлинга.
- Если понадобится термо-профиль Quicksilver, путь один — внешний датчик или
  другая ОС (проверить, объявляет ли AppleHWSensor сенсоры под Tiger 10.4;
  на Leopard 10.5.8 — нет).
