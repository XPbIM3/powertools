# fanmon — заметки тестирования (Leopard 10.5.8)

Дата: 2026-10-17. Та же машина: iMac G5 PowerMac8,1 (970FX 1.8 ГГц, PM8,1 SMU),
но загружена **Mac OS X 10.5.8 (Build 9L31a)**, Darwin 9.8.0 RELEASE_PPC.
Цель — отработать ранее отлаженный на Tiger код под 10.5. Код **не менялся**.

## 1. Сборка

- Toolchain: Xcode 3.1.4, `gcc 4.0.1 (build 5493)`, `powerpc-apple-darwin9`
- `make clean && make` — собралось **чисто, без единого ворнинга**, бинарник ~14 КБ
- Структура проекта/Makefile общие для обеих ОС, правок не потребовалось

## 2. Что работает (успехи)

- Узел с `IOHWSensors` + `IOHWControls` найден и на 10.5 — архитектура реестра
  (AppleSMU → platform plugin → оба массива) та же, что на Tiger
- Все секции вывода адекватны; масштаб 16.16 (÷65536) для temp/power/current/voltage
  сходится и здесь (idle: HDD 53.5 °C, диод 52 °C, ~19 Вт, «voltage» = та же 12-вольтовая шина ~11.6 В)
- Сенсоры живые: под нагрузкой диод 52.3 → 66.6, мощность 18.7 → 28.3 Вт;
  после нагрузки восстановление видно (66.6 → 61 за ~6 с, 28 → 17 Вт)
- Idle-базлайн по вентиляторам почти совпал с Тигром:

|      | Tiger 10.4.11 | Leopard 10.5.8 |
|------|--------------|----------------|
| actual (Sys/HD/CPU) | 1019 / 1807 / 1496 | 996 / 1796 / 1499 |
| target (Sys/HD/CPU) | 2088 / 2860 / ~1660 | 1841 / 2552 / ~1653 |

## 3. Нагрузочный тест (cpuburn -t 60 -P, mixed, duty 100%)

burn отработал честно (60.01 с, busy 100%, checksum есть).

| параметр             | idle    | под нагрузкой   | после      |
|----------------------|---------|-----------------|------------|
| CPU T-Diode          | 52.3 °C | **66.6 °C**     | 59.6 °C    |
| CPU Power            | ~18.7 Вт| **28.3 Вт**     | 16–18 Вт   |
| CPU target           | ~1660   | **1976 → 1500!**| ~1680      |
| System target        | 1887    | 1924 (медл. рост)| 1924      |
| HD target            | 2609    | 2656 (медл. рост)| 2656      |
| **actual всех 3**    | 996/1796/1499 | **не изменились ни на 1 rpm** | те же |

## 4. Открытые вопросы

1. **«Замороженные» actual воспроизводятся на 10.5.** За 60 с пикового грева
   (диод 66.6 °C, PID target живой) ни один из трёх actual не сдвинулся ни на
   один об/мин. Значит, это **не баг Tiger-драйвера** — поведение уровня SMU.
   Гипотезы (все всё ещё в воздухе):
   - **SMU-баг/особенность прошивки**: actual-значение из реестра не связано с
     реальным тахометром, либо обновляется каким-то нестандартным путём;
   - **недостаточный нагрев**: 60 с греют только диод; радиатор/корпус с их
     тепловой инерцией не прогреты — нужен непрерывный 3–5 минутный burn
     (традиционная отмашка iMac G5 — вентиляторы подхватывают с опозданием);
   - **машине нужна тепловая калибровка SMU**: на старших Power Mac G5 (PMU)
     существовала сервисная процедура калибровки вентиляторов; эта машина
     возможно не откалибрована (следы чужой прошивки/сброса NVRAM).
   Косвенная деталь: actual стоит на min/минус-квант (996 < 1000, 1796 < 1800,
   1499 < 1500) — похоже на квантованное показание «реального» тахометра, а не
   константу прошивки.
2. **CPU target на 10.5 ведёт себя иначе, чем на Tiger.** Tiger: 1660 → 2005
   (пик) → 1660. Leopard: ~1976 → **сползание к 1500 (min)** при росте
   температуры до 66 °C. Возможна другая семантика target-value в Leopard'овском
   IOPlatformPlugin либо кривой PID-профиль. System/HD target'ы при этом
   медленно, но монотонно ползут вверх — целесообразно пронаблюдать на длинном
   прогоне.
3. 60-секундный тест греет диод, но не радиатор — тест инерции вентиляторов
   (3–5 мин непрерывного burn) остаётся **невыполненным** решающим экспериментом.

## 5. Статус машины

Машина «отпускается»: основная задача (код должен собираться и корректно
читать тепловую телеметрию на Leopard) — **выполнена**. Оставшиеся вопросы
(SMU-bug vs недогрев vs калибровка) переносятся на следующий образец iMac G5:

- [ ] длительный burn 3–5 мин, снимки каждые 10 с — растут ли actual;
- [ ] параллельный контроль «на слух»/тактильно — крутятся ли физически;
- [ ] сравнить поведение с этим образцом (замороженные actual? target сползает?);
- [ ] если actual и на втором образце «заморожены» — вероятнее SMU-баг;
      если нет — ясно, что дело в калибровке/прошивке этого экземпляра.

Все наблюдения выше — на одном экземпляре, готовые тесты сохранены:
`./fanmon [-w N]`, нагрузчик `~/Projects/burn/cpuburn [-t S] [-P]`.
