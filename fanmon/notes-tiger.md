# fanmon — заметки исследования (Tiger, iMac G5 PowerMac8,1)

Дата: 2026-10-17. Машина: iMac G5, модель `wm_model = PowerMac8,1`
(Serial ATA-1 HDD 74 ГБ, GPU GeForce FX 5200, CPU 1.8 ГГц PowerPC 970FX).

## 1. Откуда берутся данные

Основной источник — **IORegistry**, сенсорная и контрольная плоскости SMU.

### Архитектура драйвера на этой машине

```
AppleSMU (com.apple.driver.AppleSMU)
├── power-mgt            (AppleSMUDevice)
├── rpm-fans@4a00        (AppleSMUDevice) → AppleSMUMonitor → IOHWControl ×3
├── sensors@d800         (AppleSMUDevice) → AppleSMUMonitor → IOHWSensor ×3
└── i2c@b, i2c@e         → IOHWSensor / IOHWControl (LM75 и co)
```

Но фанmon читает **не сервис-узлы**, а два словаря-массива, публикуемые
платформенным плагином (`SMU_Neo2_PlatformPlugin`, со стороны вложен класс
`IOPlatformPlugin` / `IOPlatformThermalProfile`):

- **`IOHWSensors`** — массив CFDictionary: сенсоры (temp / power / current / voltage)
- **`IOHWControls`** — массив CFDictionary: контроллеры (3× `fan-rpm` + 1× `slew`)

fanmon ищет узел, у которого есть **оба** массива одновременно
(`IORegistryCreateIterator` + рекурсивный обход `kIOServicePlane`),
и далее перечитывает свойства при каждом снимке.

### Масштабы значений (10.4.x)

| тип              | масштаб              | пример из реестра     | наша интерпретация |
|------------------|----------------------|-----------------------|--------------------|
| `temp`/`temperature`| ÷65536 → °C       | 3293440               | 50.2 °C            |
| `power`          | ÷65536 → Вт          | 1314191               | 20.0 Вт            |
| `current`        | ÷65536 → А (см. оговорку) | 134400          | 2.05 А             |
| `voltage`        | ÷65536 → В (см. оговорку)| 760320           | 11.59 В            |
| `fan-rpm`        | целые, прямое значение | 1807              | 1807 rpm           |
| `slew`           | флаг (0/1)           | 1                     | не выводим         |

Подтверждение масштаба — внутренний PID-профиль машины же
(`IOPlatformThermalProfile` в реестре):
- `input-target` для HD-температуры = 3801088 → **58.0 °C** — цель PID, физически правдоподобно;
- `power-max` CPU-контура = 2949120 → **45.0 Вт** — совпадает с TDP 970FX 1.8 ГГц.

### Оговорка про Voltage

`CPU Voltage` = 11.59–11.60 В — для Vcore G5 не характерно (тот, как правило,
1.1–1.5 В). Похоже, датчик меряет силовой рельс питания (12V шину), а не ядро.
„В системе также есть кривые значения“ — это то, что отдаёт реестр, мы не
выкручиваем (никаких догадок-пересчётов в fanmon нет).

## 2. Наблюдение: «замороженные» RPM при живых target'ах

### Данные (Tiger 10.4.11, 2026-10-17)

База (3 прогона подряд):

|            | System | Hard Drive | CPU |
|------------|--------|-----------|-----|
| **actual** | 1019   | 1807      | 1496|
| min..max   | 1000..4000 | 1800..6000 | 1500..4400 |
| **target** | 2088   | 2860      | ~1660 |

Под нагрузкой (cpuburn 8 с и 30 с, запуск два раза; fanmon снимки каждые ~4 с):

- CPU T-Diode: 54 → **62.7 °C** → 52.6 (реагирует ✓)
- CPU target:   1660 → **2005** → 1660     (PID живой, пересчитывает ✓)
- CPU Power:    12 → **26.6 Вт** → 12      (реагирует ✓)
- **actual всех трёх вентиляторов: 1019 / 1807 / 1496 — НЕ ИЗМЕНИЛИСЬ НИ НА
  ОДИН ОБ/МИН за всё время наблюдений (включая пиковые температуры и
  пиковые target'ы).**

### Что это значит (гипотезы, порядок уверенности)

1. **Тепловая инерция радиатора / лимит SMU по времени.** 62 °C — это диод,
   он греется секундами; алюминиевый радиатор и корпус — минуты. Известно,
   что iMac G5 разгоняет вентиляторы заметно позже диода; 30 с может просто
   не хватить (при повторе нужно ~3–5 мин непрерывного burn).
2. **`target-value` ≠ «текущая команда».** Возможно, это только текущий
   выход PID-расчёта, а команда на SMU уходит лишь при пересечении
   гистерезисных порогов. Тогдаactual стоит на «загруженном при старте»
   минимуме, пока порог не пройден.
3. **Криминальный вариант — артефакт **реестра значения** (кривой драйвер).
   Косвенно против: actual = min±(19, 7, −4) — на речной сетке
   тахометра (не ровно min, а min+квант ±гистерезисны), что похоже на
   «настоящий» показание датчика, а не константу прошивки.

### Контрольная проверка (сделать!)

Тест: **3–5 минут непрерывного burn (duty 1.0)**, fanmon в цикле каждые 5–10 с.
Если actual начнёт расти — гипотеза 1/2, а не баг. Также физически можно
визуально/по звуку убедиться, правы ли actual (вентилятор меняет скорость
или нет) — это стратегия эксперименатора.

Открытый вопрос для будущих тестов: то же самое **на 10.5 (Leopard)** —
другая версия IOFamily, другой AppleSMU; реестровая цепочка может быть
исправлена.

## 4. Переносимость (для будущих машин)

- SMU-платформа (iMac G5 все ревизии, Power Mac G5 7,x): должно работать
  как есть (могут отличаться названия/датчики=количество).
- PMU-платформа (G4-тары, PowerBook/iBook, mini G4): вряд ли — узел с
  обеими массивами может не существовать; fanmon корректно выйдет с
  «unsupported machine?».
- Intel-маки: нет (SMC-архитектура); так же корректно откажется.
- Масштабы 16.16: подтверждены две сходимости (58 °C target и 45 Вт max)
  на этой машине; на других SMU-версиях могут отличаться — сенсор `voltage`
  уже сейчас читается как «рельс», а не Vcore.
