# cpubench

Синтетический бенчмарк CPU для PowerPC Mac (Mac OS X 10.4/10.5, G4/G5).
Замеряет два числа — скалярную FP-пропускную способность и целочисленную
ALU-пропускную способность. Одна утилита, чистый C, вне мониторинга железа.

## Метрики

| фаза | ядро | за пасс | отчёт |
|------|------|---------|-------|
| **FP**  | 16 независимых цепочек `a = a*x + 0.5` (native `fmadd`, dbl 64-bit) | 16 FMADD = 32 флопа | FMADD/s и **GFLOP/s** |
| **INT** | 4 цепочки xorshift32 (только xor/shift, latency 1 такт) | 8 раундов × 4 линии × 6 op = 192 ALU op | **million ALU ops/s** |

## Почему так (а не «рандомные операции»)

1. Ядра **детерминированные** и с точным счётом операций — «случайность» не
   влияет на пропускную способность конвейера, зато ломает её учёт.
2. Фаза выполняется **чанками ~0.35 с**: часы читаются один раз за чанк и в
   конце фазы — overhead < 0.5 %, а метрика считается как «операции / фактическое
   wall-время», так что замер самокорректный.
3. **Прогрев перед каждой фазой** (неучитываемый чанк): 970FX/G4 просыпаются
   из простоя на пониженном P-state и разгоняются по ходу; без прогрева
   калибровка завышала/занижала реальную скорость до 40 %.
4. Итоговый чексумма печатается в конце — доказательство, что работа
   не выброшена оптимизатором (и свидетельство, что машина считает честно).

## Запуск

```
./cpubench            # FP 10 с + INT 10 с (итого ~21 с с калибровкой)
./cpubench -t 3       # быстрее для дымогонных проверок
```

Вывод: по каждой фазе число операций, реальное wall-время, миллионы операций
в секунду; в конце — общий чексумма и суммарное время.

## Сборка

Единые флаги репозитория: `gcc -std=gnu99 -O2 -Wall` на обеих ОС,
0 warnings. AltiVec не нужен (метрика скалярная).

## Дизайн-решения

**Multi-core режим НЕ делаем** (решение 19.10.2026, отказ от предложения
OpenCode-сессии). Суть проекта — сравнимость **одноядерной** производительности:
паспорта мерят одну ячейку, что и позволяет сравнивать G3/G4/G5 меж собою
по такту. Считать ядра машины — не наша задача; нагрев обоих ядер, если
потребуется, делает cpuburn.

Если решение когда-нибудь пересмотрят: sketches — `-j N` (0 = auto через
sysctl hw.ncpu, вне дефолта), pthread_create + независимые детерминированные
ядра per-thread, чексуммы агрегируются XOR-ом; на G3/G4 (hw.ncpu=1) путь
вырождается без регрессии. Интересный нетронутый вопрос: FP ×2 на 2-сокетном
PowerMac7,3 против разделяемого-FSB dual-core iMac 970FX (bus contention).
