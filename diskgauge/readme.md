# diskgauge

**НЕ тулза. Это эталонный пример сборки трей-утилиты** — третья ступень
парк-каркаса GUI (`carbon-probe` окно → `traycpu` CPU-гейдж → здесь
дисковый гейдж). Смысл — записать рецепт: где собирали, куда ставили,
какие грабли по ширине/счётчикам. Цифры в трее — способ показать рецепт.

## Что делает

Один пункт меню-бара, системно-широкая скорость диска в моменте:

```
 HDD: W: 050 R: 003 MB/s
```

- Без главного окна, без док-иконки (`LSUIElement=1`, агент с 10.0)
- Меню единственный пункт «Выход» → `[NSApp terminate:]`
- Обновление 1 Гц, `NSTimer` в `NSDefaultRunLoopMode` (при открытом меню
  счёт стоит — косметика)
- Первая секунда показывает ` W: -- R: -- ` (нужен базовый снапшот)

## Собиралось / ставилось

- **Хост сборки**: intel-leopard (MacBookPro3,1, Mac OS X 10.5, gcc
  i686-apple-darwin9-gcc-4.0.1 b5493) — кросс в PPC
- **Цель**: PowerMac3,1 Sawtooth G4-7400 @400, **Panther 10.3.9**
  (машина `powermac-g4-400` / 10.0.1.29)
- Протокол запуска — общий для каркаса: минимальный бандл `DiskGauge.app`
  (Info.plist + MacOS/бинарь), несжатый `tar` (на чистой Пантере нет
  gzip), `scp -O`, `open ~/DiskGauge.app`; `-psn_…` в `ps` = запуск в
  консольной сессии

## Рецепт

```sh
gcc -arch ppc -mcpu=G3 -Wl,-force_cpusubtype_ALL \
    -mmacosx-version-min=10.3 -std=gnu99 -O1 -Wall \
    -fobjc-abi-version=1 \
    -x objective-c diskgauge.m -o diskgauge \
    -framework Foundation -framework AppKit -framework IOKit
```

- `-fobjc-abi-version=1` — только objc1-классы (Panther-runtime);
  `otool -ov` декодирует `ProbeTarget`/`tick:` в легаси-форме
- Leopard-нюанс: **зонтичного `IOKit/IOKit.h` нет** — цеплять
  `<IOKit/IOKitLib.h>` напрямую
- Аудит артефактов: **PPC ALL**, VA=0
  - бинарь гейджа md5 `4d17b65125e2c83db5735a9d4742b99a`
  - пробник md5 `ad957be17d69d0d5a35313fe890a6a19`
- ObjC — одни objc1-конструкции; кириллица «Выход» — UTF-8 литерал через
  `stringWithUTF8String`

`make` собирает `diskgauge` + бандл + `dgprobe` (CLI-пробник).

## Первоисточник цифр

Не опрашиваем скорость — раз в секунду читаем накопительные счётчики
ядра: IOKit-драйвер `IOBlockStorageDriver` публикует в реестре
свойство `Statistics` (суммарные байты с загрузки). Дельта двух
снапшотов через 1 с = мгновенная скорость всей системы; ядро само
интегрировало между визитами. Чтение реестра — ноль дискового I/O.

**Пантер-находка (ioreg, ключи асимметричны):**
`"Bytes (Read)"`, но `"Bytes (Write)"` — без `n`. Читаем оба написания
(`Bytes (Write)` → фолбэк `Bytes (Written)`), по факту носителя.

## Анти-пляску: как держать ширину строки

Ядро решения (по спеке юзера): **скорость — целые MB/s в фиксированном
3-знаковом поле с ведущими нулями**, кап 999: `000`, `007`, `050`,
`119`, `999`. Дробями не думаем, стрелок и трендов нет. Длина строки —
константа при любом раскладе цифр.

Происхождение (история отбора, тоже урок рецепта):

| итерация | решение                                              | итог на живой машине        |
|----------|------------------------------------------------------|-----------------------------|
| v1       | `%03d` без нулей + авто-мера ширины (+10 pt)         | правый край съедался        |
| v1.5     | тот же формат, +30 pt                                | правый край съедался снова  |
| v2¹      | затея с моноширинным NSView-рендером                 | **отклонена юзером — не нужны** |
| v2¹      | стрелки-тренды ▲▼ возле значений                     | **отклонены — «стрёмно»**   |
| финал    | `%03d` нулевые поля + щедрый **+50 pt** к авто-мере   | **9/10, принято**           |
¹ v2 была не собрана (свернута до постановки на сборку — «если сложно — брось», оценено честно: не сложно, но лишнее).

Формула длины пункта: `[widest(" HDD: W: 999 R: 999 MB/s ")
sizeWithAttributes:]` ширина мелким системным шрифтом + 50 pt.
Пантер-пункт НЕ авторесайзится под `setTitle:` — длина держится фикс.

## dgprobe — объективная кросс-сверка

CLI-пробник тех же счётчиков (тот же IOKit-запрос, без AppKit): `./dgprobe N`
печатает N секунд скорости + накопители. Живой замер на машине:

```
tick 3: R 0.0  W 8.6 MB/s   (cum W 1213.8 MB)
tick 4: R 0.1  W 1.7 MB/s   (cum W 1215.4 MB)
```

— dd 10 MB вспышкой разлился на 2 тика (8.6+1.7 ≈ 10.3 MB с
метаданными ФС), **никакого лимита в гейдже нет** — короткие вспышки
dd упираются в write-back кэш ФС (768 MB RAM) темпом ~9–10 MB/s;
устойчивые последовательные 30.4 MB/s мерил diskbench отдельным
паттерном. Кэш- нюанс: чтение мелкого/недавно-писанного файла даёт
**R = 0.0** — FS-cache обслужил из RAM, до диска I/O не дошёл. Это
честная семантика: R/W показывают именно disk-I/O, не fs-calls.

Накопители тоже читаемы (с загрузки: R 1289–1642 MB / W 1205–1734 MB
по ходу дня) — пробник их печатает в скобках.

## Деплой-грабли (запись в копилку)

- **Двужильный глюк тара**: раз за разом `tar xf` или `scp -O` тара
  пролетает молча → «Cannot open: (null)»/открытие не удалось. Лечение
  в рецепте: **md5 тара сверять на обоих концах** до расформирования;
  при несовпадении/ошибке — пересоздание тара начисто
- Panther-ключи: только `Bytes (Write)` (см. выше)

## Границы

- `--` первую секунду после старта
- R = 0 на кэш-чтениях (семантика настоящих дисковых I/O)
- Таймер стоит, пока открыто меню
- Разрядность: только целые MB/s, то есть 0.5–0.9 MB/s показываются
  как `001`
